# 情境全圖（cruise-door-studio 版）

**想功能的時候只會想到順利的那條路。** 讀不到的檔案、存不了的瀏覽器、做到一半關掉、兩個分頁同時開、印出來尺寸不對，多半沒有人想過，也沒有人寫過文案。

寫 code 的時候，這些洞會被**自己默默補上**：補的文案沒人看過，補的行為沒人知道。等到真的拿去 7-11 印才發現，那時候改最貴。

這道 skill 把補洞提前，而且畫出來讓 Una 看得見。

## 🔴 預設不畫，先問

畫一張圖要花不少時間，很多改動不需要。改文案、調樣式、修一個 bug、加一個開關，直接寫 code 就好。

先把需求讀完，判斷值不值得盤。值得就問一句：

> 這個功能的情境我可以先盤一遍、畫成流程圖給你看，避免我自己補的洞沒人確認。要嗎？

**說要才畫。說不用、或沒回答，就直接寫 code。**

| 值得問 | 不用問，直接做 |
|---|---|
| 新步驟、新頁面、新的多步驟操作 | 改文案、調樣式、修單一 bug |
| 新的輸入或輸出：上傳、匯入專案檔、下載 PDF、列印 | 純重構、行為不變 |
| 動到存檔、復原、排版這種會讓人掉資料或印錯的邏輯 | 只有一條路、沒有失敗的可能 |
| 新增門款、紙張、列印地點（尺寸對不對直接影響印出來的東西） | 加一個欄位、換一個圖示 |

拿不準就問一句，不要自己決定畫下去。

## 一、盤情境：照使用者操作的順序，一段一段問

使用者是**要去搭郵輪、想裝飾艙門的一般人**，不是設計師，多半第一次用。照「他做到哪一步」分段，不要照程式結構分。每一段問同樣五題：

1. **這一步可能完全不出現嗎？** 自訂尺寸的門沒有門牌、門鎖和禁貼區；無痕視窗存不了檔；第一次來門上只有範例。
2. **他可以中途離開嗎？** 關分頁、重新整理、按 Esc、點彈窗外面、PDF 產生到一半離開。做到一半的東西還在嗎？該清掉的有清掉嗎？
3. **瀏覽器可能失敗在哪？** 這個網站沒有後端，失敗都來自瀏覽器：
   - 圖片解不開（HEIC、壞檔、不是圖片）
   - IndexedDB 存不了（無痕、封鎖網站資料、空間不夠）
   - canvas 太大或記憶體不夠（大張 PNG、切塊、350 dpi 的 A1）
   - 下載被擋（一次下載多個檔案）
4. **有沒有網站偵測不到的？** 7-11 機台或家用印表機自己縮放、使用者在 ibon 選錯紙張、瀏覽器默默擋掉第二個下載。這種只能靠文案提醒，圖上畫灰色虛線。
5. **跟別的操作交叉會怎樣？** 兩個分頁同時改、復原跨過「開啟專案檔」、換門款之後貼紙跑到門外、換紙張之後原本放得下的變成放不下。

額外一定要問的三題：

- **哪些是正常分支，不是錯誤？** 例如貼紙蓋到禁貼區只是提醒，還是可以放；放不下的貼紙有「縮小」和「切塊」兩條出路。誤當成錯誤，會讓人以為壞掉了。
- **有沒有靜默失敗？** 做錯了但畫面看起來成功，最危險，永遠標紅。這個專案最容易出現的：
  - 下載被瀏覽器擋，提示卻說「已下載 3 個 PDF」
  - 兩個分頁同時存，後存的默默蓋掉先存的
  - 檔案被 filter 掉，什麼提示都沒有
  - 熱更新後圖片快取和排版不同步，存下指向不存在圖片的貼紙
- **用通用提示就夠，還是要專屬文案？** 失敗都透過 `useUi().notify()` 跳 toast，**不會自己出現**，每一條失敗路徑都要自己呼叫。只有「看了通用提示會不知道要改哪裡」的才需要專屬文案，例如「讀不到『IMG_2041.HEIC』，請換成 PNG、JPG 或 SVG」要寫出檔名。

每張圖都要檢查一次這幾種狀態：**門上還沒有貼紙**、**範例貼紙還在**、**很多張（16 張以上）**、**一張超大（70 cm 寬）**、**手機寬度**。

## 二、畫成流程圖，不要列清單

**清單沒有用**。表格、卡片、條列都算清單，看的人沒辦法在腦中拼出畫面。要畫成真的流程圖：有主線、有箭頭、會分岔，而且**節點就是使用者當下看到的畫面**。

### 動手前先打開參考成品

- 發布版：https://claude.ai/artifact/XyVUSGQCJ6p2YrtFWcgbdg
- 原始檔：`docs/scenario-map.html`

**直接改原始檔，不要重寫一套。** 版型和縮圖都在裡面：

| 要改的 | 在哪 |
|---|---|
| 頂部「要決定什麼」 | `decide` 陣列，每項 `D('節點編號', '白話描述')` |
| 每一段流程 | `parts` 陣列。節點 `['B3', 'err', 畫面, '一行註記']`；箭頭 `{ a: '條件' }`；判斷點 `{ g: '問句' }`；本機運算 `{ api: '說明' }`；分岔 `{ fork: [['lane 條件', 節點...], ...] }` |
| 畫面縮圖 | `arrange({...})` 排在門上、`print({...})` 印刷頁、`editor({...})` 去背視窗、`paper('...')` 印出來的紙；用 `toast`、`right`、`warn`、`stickers` 等參數換內容 |

改完用 Artifact 工具發布到**同一個網址**（從別的對話更新時傳 `url`），再把 `docs/scenario-map.html` 一起 commit。

### 規格

- **主線由上往下**，條件寫在箭頭上，不要寫在節點裡。
- **四色語意**：綠＝正常；紅＝錯誤或死路；黃＝文案或畫面待決定；灰虛線＝刻意不處理或網站偵測不到。
- **框內框外分兩套語言**：
  - 框內＝使用者真的看得到的畫面，用**元件裡真實的文案**（先 `grep -rn "notify(" src` 找現成的句子），顏色用 `src/style.css` 的 tokens
  - 框外＝編號、註記，使用者看不到
  - 不要把工程註記畫進畫面框裡
- **每個節點一句話**。節點只有 252px 寬，放得下第三行就是寫太多了。
- **節點要掛在正確的位置**。例如「整張都去掉了」是按「套用」時才擋，不是點的時候；「放不下」在選取貼紙時就看得到，不是等到下載。畫之前先確認那個狀態真的到得了。
- **頂部放「要決定什麼」**，逐條標節點編號；**已定案的另外列一行**，免得同一個問題被問第二次。

### 踩過的雷

| 雷 | 正解 |
|---|---|
| 分岔裡再巢一層分岔，lane 被壓得比縮圖還窄 | 第二層分岔拆成獨立一段，上一段結尾留一個 `{ g }` 判斷點承接 |
| lane 一多就被壓扁 | `.fork` 有 `min-width: calc(var(--n) * 270px)`，外層 `.scroll` 會橫向捲動，不要拿掉 |
| 輔助函式取名 `top` | 會撞到 `window.top` 整頁不顯示，已改成 `topBar` |

## 三、先擬文案可以，但要標得找得到

這個專案沒有 i18n，文案直接寫在元件裡。

| 情況 | 怎麼做 |
|---|---|
| 專案裡已有的句子 | 直接用，同一件事用同一個說法 |
| Una 已經定案 | 用，圖上的「已定案」那行補上 |
| **還沒定** | 先擬一句寫進 code，旁邊加 `// TODO:待 Una 確認 —— 為什麼這樣擬`；圖上那個節點標黃 |

`grep -rn "TODO:待" src/` 要能撈出所有未定文案。

### 🔴「加一個沒人要求的元素」要先問

擬文案是填既有的洞；多加一個畫面上沒有的東西，是自己開新洞，要先問。

| | 可以自己擬 | 要先問 |
|---|---|---|
| 既有位置換一句話（toast、按鈕字、警告） | ✅ | |
| 新增一整個元素（確認彈窗、說明區塊、新按鈕） | | ✅ |
| 改變既有元素出現的條件 | | ✅ |

改畫面的操作或排版時，照 `una-ui-ux` skill 的流程走，交付附上「主要任務路徑」和「控制項異動」。

## 四、畫完之後：給 Una 的待決清單

用**白話講現場**，不要寫 code 用語：

> ❌ `buildPdfs` 回傳多個 blob 時 `downloadBlob` 被 Chrome 擋
> ✅ 用 ibon 印 16 張時檔案會拆成 3 個 PDF，Chrome 可能只讓第 1 個下載，畫面卻說「已下載 3 個」。要改成打包成一個 zip，還是列出 3 個按鈕讓人一個一個按？

分三類：**缺文案的**、**缺畫面的**、**規則要決定的**（例如兩個分頁同時改，要不要擋）。

## 五、定案之後、寫完之後

- 定案 → 改進 code，把圖上的黃色節點改成對應顏色，並移到「已定案」那行
- 情境被砍 → 圖上直接刪掉，不要留著
- 有新情境 → 補進圖，重新發布到同一個網址
- **寫完 code 要拿圖當檢查表**，每條岔線都回去追一次程式真的有那條路，特別是：紅色死路的出路走得到嗎？中途離開該清的有清嗎？靜默失敗那幾條有沒有變成「畫面顯示成功但其實沒做」？能寫成 Vitest 的（排版、切塊、尺寸計算）就寫成測試，跟 `src/domain/packing.test.ts` 放在一起
